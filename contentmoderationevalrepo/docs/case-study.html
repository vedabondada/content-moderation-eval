Portfolio · Project 1

Content Moderation Classifier with an Evaluation Harness

An AI system that flags harmful comments for human review, built and evaluated on the public Jigsaw dataset, running on the lowest-cost model.

Problem statement

MidSize Co (a representative client) runs a community platform with about 2 million monthly users. Its comment-moderation queue is roughly 48 hours behind, user complaints are rising, and slow response to threats and hate speech creates legal exposure. The goal is to use Claude to read incoming comments and flag the likely-harmful ones for a human moderator to review — not to delete anything automatically. The main work is not building the classifier; it is measuring it well enough to trust in production.

Process

1

Scoped a first version

I limited v1 to English-language text comments and the six Jigsaw categories (toxic, severe-toxic, obscene, threat, insult, identity-hate), producing a separate score per category. I left images, video, and other languages out of scope, and kept the system to flagging for review rather than automatic removal.

2

Defined success in business terms

Because missing harmful content is worse than a false alarm — a human reviewer clears false alarms downstream — I optimized for recall (catch rate) and used precision as a guardrail so reviewers are not overwhelmed. I set the targets at a 95% catch rate for the three high-severity categories (threat, severe-toxic, identity-hate) and 85% for the rest.

3

Built the evaluation set

I used the Jigsaw dataset (about 160,000 human-labeled comments) as the answer key. I built the evaluation set by stratified sampling rather than random sampling: threats make up only about 0.3% of the data, so a random 2,000-comment sample would contain roughly six threats — too few to measure a 95% catch rate against. Instead I took all 478 threats, over-sampled the other rare categories, and added a block of clean comments to measure false alarms. The result was a 4,378-comment evaluation set with enough of every category to measure.

4

Built the classifier

I wrote a prompt instructing Claude to return a confidence score from 0 to 1 for each of the six categories, with definitions for each. I ran it on the lowest-cost model (Claude Haiku) so that cost would be established as a baseline before considering anything more expensive.

5

Ran the baseline

On the first full run with default settings, the classifier met the target on 2 of 6 categories. Obscene, identity-hate, severe-toxic, and threat all fell short. This established the starting point for improvement.

6

Tuned the flag thresholds

Each category has a cutoff that decides how high a confidence score must be before the comment is flagged. Lowering those cutoffs per category — flagging more readily where missing content is costly — improved obscene and identity-hate to their targets at no additional cost, since it only re-reads scores already produced. This brought the system to 4 of 6.

7

Revised the prompt, including a change that made things worse

I broadened the definition of "threat" to include wishing serious harm, illness, or death on a person. That raised the threat catch rate to 98%, above target. In the same revision I tightened the definition of "severe-toxic" to only the most extreme cases and told the model to prefer the milder label when unsure. This over-corrected: the severe-toxic catch rate dropped sharply. The change to threat helped; the change to severe-toxic did not, so I kept the first and reverted the second. Prompt changes affect categories independently and need to be measured, not assumed.

8

Checked whether a stronger model was needed

The remaining question was severe-toxic, and the common assumption would be to move to a stronger, more expensive model. Before recommending that spend, I ran the low-cost model and a stronger model on the same 60 comments with the same prompt. Both produced the same catch rate on this sample. On this evidence, a model upgrade was not the fix, so I did not pursue it.

9

Interpreted the severe-toxic result

Severe-toxic still fell short as a standalone number. However, every severe-toxic comment in the dataset is also labeled toxic (1,595 of 1,595), and the classifier catches 100% of toxic comments. So every severe-toxic comment is already flagged for review under the toxic label — nothing harmful goes unreviewed. The standalone severe-toxic metric is low, but the business requirement (no harmful comment reaches users unreviewed) is met. The remaining limitation is that the severe-toxic signal is too noisy to reliably rank comments by severity, which would matter only if strict worst-first triage were required.

10

Final results and decision

The system runs on the lowest-cost model with per-category thresholds and the revised prompt. Five of six categories meet target on their own, and the sixth (severe-toxic) is covered through the toxic label. No spend on a more expensive model was needed.

What I built

  • A per-category content-moderation classifier built on the Anthropic API.
  • A Python evaluation harness: stratified sampling, per-category precision/recall against targets, threshold tuning, and a cheap-vs-stronger model comparison.
  • A model-selection decision supported by measurement rather than assumption, reached for a few dollars of total spend.
